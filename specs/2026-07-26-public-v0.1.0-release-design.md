# Public v0.1.0 Release Design

## Goal

Publish Workbook v0.1.0 as a real, installable macOS command-line release so
it can be tested from a clean system with Homebrew.

## Scope

The first public release supports macOS only:

- Apple Silicon (`darwin/arm64`)
- Intel (`darwin/amd64`)

The public artifacts are a GitHub Release for tag `v0.1.0` and a formula in
the public `dgoings/homebrew-tap` repository, installable as:

```sh
brew install dgoings/tap/workbook
```

Linux packages, automated migration to a future Workbook organization, package
signing/notarization, release-note generation, and other package managers are
outside this release.

## Release Artifacts

For version `0.1.0`, the release creates exactly:

```text
workbook_0.1.0_darwin_arm64.tar.gz
workbook_0.1.0_darwin_amd64.tar.gz
checksums.txt
```

Each archive contains only the `workbook` executable. `checksums.txt` contains
SHA-256 digests for both archives in a stable standard format.

The binary exposes `workbook version` and reports the semantic version and the
Git commit injected at build time. Development builds use an explicit `dev`
version rather than claiming a released version.

## Release Workflow

A GitHub Actions workflow triggers only for pushed tags matching `v*`. It:

1. checks out the exact tag;
2. runs the full Go test suite;
3. cross-compiles the two macOS binaries with version and commit linker flags;
4. archives them and generates checksums;
5. creates or updates the corresponding GitHub Release and uploads all three
   artifacts; and
6. updates `Formula/workbook.rb` in `dgoings/homebrew-tap` with the release
   URLs and SHA-256 values.

The tap update uses a dedicated repository credential stored as a GitHub Actions
secret. The secret must have access only to `dgoings/homebrew-tap`; it is never
printed or committed. A failed tap update fails the workflow rather than
claiming that the release is Homebrew-installable.

Repository owner/name values are centralized as workflow configuration so a
future transfer changes a small, explicit set of settings. v0.1.0 does not add
migration behavior.

## Homebrew Formula

`Formula/workbook.rb` chooses the release archive by macOS CPU architecture,
uses immutable GitHub Release URLs and checksums, and installs the contained
executable into Homebrew's `bin`. It declares macOS as the supported platform
and includes a `test do` block that executes `workbook version`.

The formula is generated or updated from the same release artifact metadata;
checksum values must never be duplicated manually in workflow configuration.

## Validation

Automated coverage verifies:

1. version output for development and linker-injected release builds;
2. artifact names, executable-only archive contents, and checksums;
3. formula rendering for both supported architectures and use of the exact
   generated SHA-256 values; and
4. workflow syntax and that it triggers only from version tags.

The release acceptance test happens after publication on a clean macOS system:

```sh
brew install dgoings/tap/workbook
workbook version
git init workbook-release-smoke && cd workbook-release-smoke
workbook init
workbook create "Release smoke test"
workbook list
```

The installed binary must report `0.1.0`; initialization and CRUD must succeed.

## Publishing Guardrails

The workflow and local tooling construct artifacts deterministically from a
specific tag. Publishing the actual `v0.1.0` tag, GitHub Release, and tap
formula is an explicit final action authorized for this task. Before that
action, the implementation must pass its full suite and the release workflow
must be reviewed.
