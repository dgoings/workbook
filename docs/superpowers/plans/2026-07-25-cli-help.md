# CLI Help Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make every Workbook command discoverable through consistent global, command, and hooks-subcommand help.

**Architecture:** Extend the existing command schema into one authoritative metadata model for parser validation and help rendering. Dispatch recognized help requests before normal command execution, so help never opens a repository or changes task state; retain the existing invocation-error path for malformed/unknown help requests.

**Tech Stack:** Go standard library flag package, existing internal/cli dispatcher and tests.

## Global Constraints

- Global, command-local, and explicit help output is always human-readable text and exits zero.
- The help command accepts no flags; help targets are only a top-level command and, for hooks, its install subcommand.
- Existing command option schemas remain authoritative; help options must match registered options exactly.
- Help does no Git I/O, repository initialization, server startup, or task-ref mutation.
- Keep current JSON-error behavior for non-help invocations and preserve all existing command semantics.
